# Phase 7G — LIFF Redirect Loop Fix + Fast Online Loading

รอบนี้แก้ปัญหาที่พบจากการทดสอบจริง:

- เปิดลิงก์ LIFF แล้ว URL ซ้อน `liff.state` / `liffRedirectUri` หลายชั้นจนวนลูป
- ลูกค้าเปิดหน้าสะสมแต้มใช้เวลานานประมาณ 1 นาที
- ลูกค้ากดลิงก์รับแต้มแล้วช้า
- ลูกค้ากดแลกรางวัลแล้วรอลิงก์อนุมัตินาน
- หลังบ้านสร้างลิงก์รับแต้มแล้วรอนาน เพราะเรียกโหลด snapshot ทั้งระบบหลัง action สำเร็จ

## สิ่งที่แก้

1. หน้า Customer production ไม่รอโหลด `/api/db/snapshot` ทั้งระบบก่อนแสดงหน้าแล้ว
2. เพิ่ม API `/api/db/customer-state` สำหรับโหลดเฉพาะข้อมูลที่ลูกค้าต้องใช้ในร้านนั้น
   - ร้านปัจจุบัน
   - ลูกค้าตาม LINE ID / customer ID
   - ของรางวัลของร้าน
   - banner ของร้าน
   - membership tiers ของร้าน
   - transactions ของลูกค้าคนนั้น
   - coupon ของร้านหรือ coupon ตาม code
3. หลังรับแต้มและหลังแลกรางวัล ไม่เรียก `initializeDatabase()` เพื่อโหลด snapshot ทั้งระบบอีกแล้ว
4. หลังสร้างลิงก์รับแต้มในหลังบ้าน ไม่เรียก `refreshFromNeon()` ทั้งระบบแล้ว แต่ใช้ข้อมูล coupon ที่ API ยืนยันสำเร็จมาแสดงทันที
5. เพิ่มการ clean URL ของ LIFF ให้ลบพารามิเตอร์ของ LINE เช่น `liff.state`, `liffClientId`, `liffRedirectUri`, `liff.hback`, `state`, `code` ที่ LINE เติมเข้ามา ไม่ให้ redirect ซ้อนกัน
6. route handler ที่เป็น action สำคัญไม่เรียก `ensureCrmSchema()` ทุก request แล้ว เพราะ production/pilot ควรรัน migration แล้ว ทำให้ action เร็วขึ้น

## ต้องรัน SQL ไหม

ไม่ต้องรัน SQL ใหม่

## จุดที่ควรทดสอบ

1. เปิด Rich Menu ไปหน้าแต้มของฉัน
2. เปิด Rich Menu ไปหน้าของรางวัล
3. เปิดลิงก์รับแต้มจาก LINE
4. ลูกค้ากดรับแต้ม ควรสำเร็จภายในไม่กี่วินาที ไม่ใช่ประมาณ 1 นาที
5. ลูกค้ากดแลกรางวัลแล้วควรได้ลิงก์ส่งร้านภายในไม่กี่วินาที
6. หลังบ้านสร้างลิงก์รับแต้มแล้วตารางควรอัปเดตทันที
7. URL หลังเปิด LIFF ต้องไม่ซ้อน `liff.state` ยาวหลายชั้นอีก

## ข้อจำกัดที่ยังเหลือ

- หลังบ้านบาง action ที่เป็นการตั้งค่าหรือรายงานใหญ่ยังอาจใช้ full snapshot เมื่อกดปุ่มรีเฟรชเอง
- ถ้า Vercel/Neon cold start อาจช้าเล็กน้อย แต่ไม่ควรช้าระดับ 1–3 นาที
