# Pilot Hardening Checklist — ก่อนเปิดใช้งานจริง

เอกสารนี้เป็น checklist สำหรับตรวจระบบ Customer Loyalty CRM หลังจบ Phase 6G เพื่อให้ร้าน `im-sticker` พร้อมทดสอบ Pilot จริง โดยเน้นตรวจ flow หลัก ไม่เพิ่มฟีเจอร์ใหม่

## 1. ตรวจ Environment / Deployment

- [ ] รัน Neon migrations ครบตามลำดับ `002` ถึง `007`
- [ ] Vercel มี `DATABASE_URL` หรือ connection string ที่ระบบใช้อยู่
- [ ] Vercel มี `BLOB_READ_WRITE_TOKEN` ของ Blob Store แบบ Public
- [ ] Blob Store ที่ใช้สำหรับรูปภาพเป็น Public store
- [ ] หลังแก้ Environment Variables มีการ Redeploy แล้ว
- [ ] `npm install` ใช้ registry ปกติ `https://registry.npmjs.org/`
- [ ] `npm run typecheck` ผ่าน
- [ ] `npm run build` ผ่าน

## 2. ตรวจ Customer Flow

- [ ] เปิด `/customer/im-sticker` ได้
- [ ] แสดงชื่อร้าน โลโก้ รูปโปรโมชัน และข้อมูลร้านถูกต้อง
- [ ] แสดงแต้มปัจจุบันและระดับสมาชิกถูกต้อง
- [ ] แสดงแต้มใกล้หมดอายุ ถ้ามีรายการที่เข้าเงื่อนไข
- [ ] เปิดหน้า “ของรางวัล” ได้
- [ ] กดขอแลกรางวัลแล้วได้ลิงก์ส่งให้ร้าน
- [ ] ประวัติการรับแต้ม/แลกรางวัลแสดงถูกต้อง

## 3. ตรวจ Point Claim Flow

- [ ] Merchant สร้างลิงก์รับแต้มได้จากหน้า “รับแต้ม”
- [ ] อายุลิงก์ตั้งเป็นนาทีในหน้า “รับแต้ม” เท่านั้น
- [ ] ค่าเริ่มต้นของอายุลิงก์คือ 10 นาที
- [ ] Customer กดรับแต้มจากลิงก์ได้ 1 ครั้งต่อคูปอง
- [ ] กดซ้ำจากคูปองเดิมแล้วระบบไม่ให้รับซ้ำ
- [ ] ลิงก์หมดอายุแล้วระบบแจ้งถูกต้อง

## 4. ตรวจ Reward Approval Flow

- [ ] หน้า Merchant → “อนุมัติรางวัล” มีช่องตรวจสอบลิงก์รับรางวัล
- [ ] วางลิงก์จากลูกค้าแล้วกดตรวจสอบได้
- [ ] ลิงก์ถูกต้องเปิด popup อนุมัติ/ไม่อนุมัติ
- [ ] กดอนุมัติแล้วสถานะรายการเปลี่ยนถูกต้อง
- [ ] กดไม่อนุมัติแล้วคืนแต้ม/สถานะถูกต้องตาม logic ปัจจุบัน
- [ ] ลิงก์ผิดเปิด popup แจ้งลิงก์ไม่ถูกต้องและปิดได้
- [ ] เปิดลิงก์ตรง `/merchant/{slug}?merchantTab=approvals&redeem={transactionId}` แล้วตรวจอัตโนมัติ

## 5. ตรวจ Merchant Settings

- [ ] ตั้งค่าข้อมูลร้านได้ เช่น ชื่อร้าน คำอธิบาย เบอร์โทร สถานะร้าน
- [ ] อัปโหลดโลโก้ร้านผ่าน Vercel Blob ได้
- [ ] Refresh หน้าแล้วโลโก้ยังอยู่
- [ ] ตั้งค่ากฎสะสมแต้มได้ เช่น ปัดเศษ ยอดขั้นต่ำ แต้มหมดอายุ
- [ ] ตั้งค่าระดับสมาชิกได้
- [ ] ปรับลดแต้มแล้วระดับสมาชิก downgrade ถูกต้อง
- [ ] Pilot Checklist บันทึก checkbox ได้และ refresh แล้วยังอยู่

## 6. ตรวจ Image Storage

- [ ] อัปโหลดโลโก้ร้านใหม่ได้
- [ ] อัปโหลดรูปของรางวัลใหม่ได้
- [ ] อัปโหลดรูปโปรโมชัน/banner ใหม่ได้
- [ ] รูปใหม่แสดงหลัง refresh
- [ ] รูปใหม่แสดงบนหน้าลูกค้า
- [ ] รูปเก่าแบบ data URL ยัง fallback แสดงได้ ถ้ายังไม่มี URL ใหม่

## 7. ตรวจ Export / Report / Reset

- [ ] หน้า “รายงาน” เปิดได้
- [ ] Export CSV ลูกค้าได้
- [ ] Export CSV ประวัติแต้มได้
- [ ] Export CSV แลกรางวัลได้
- [ ] Export CSV ลิงก์รับแต้มได้
- [ ] Reset tools ใช้งานได้เฉพาะเมื่อตั้งค่า env ที่อนุญาตไว้
- [ ] ก่อนเปิดจริงต้องแน่ใจว่าไม่ล้างข้อมูลผิดร้าน/ผิดฐานข้อมูล

## 8. ข้อจำกัดที่ยังตั้งใจคงไว้

- ยังไม่หักแต้มหมดอายุอัตโนมัติ
- ยังไม่ทำ FIFO point lots ตอนแลกรางวัล
- ยังไม่ทำ cron job รายวัน
- ยังไม่ลบไฟล์เก่าใน Vercel Blob อัตโนมัติ
- ยังไม่ลบ column รูปเดิมที่เป็น data URL เพื่อความปลอดภัยของข้อมูลเก่า

## 9. เกณฑ์ผ่าน Pilot Hardening

ถือว่าพร้อม Pilot เมื่อผ่านอย่างน้อย:

- Customer รับแต้มได้
- Customer แลกรางวัลได้
- Merchant อนุมัติรางวัลจากลิงก์ได้
- Merchant ปรับเพิ่ม/ลดแต้มได้ และระดับสมาชิกถูกต้อง
- รูปใหม่จาก Vercel Blob แสดงหลัง refresh
- Export CSV หลักใช้งานได้
- ไม่มี error build/deploy
